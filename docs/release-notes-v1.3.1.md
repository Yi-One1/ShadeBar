# 随影 ShadeBar v1.3.1

修复两处真机缺陷：**一部分指示条永久不改色**、**偶尔整片不着色且重启软件也救不回来**。
另把"所有正常态指示条统一改色"落到结构上——它们现在共用一个画刷，同一刻变色。

## 修复

- **一部分指示条永久不改色，重启软件也补不回来。**
  载荷只在订阅 XAML 诊断时拿到一次元素树，之后仅靠"带名字的 Add"增量维护；实测打开新窗口
  时日志里 **0 条 `[Add]`**，新指示条永远进不了树。宿主重启时 DLL 已驻留、`DllMain` 不再
  执行，也不会重新订阅，于是漏掉的元素永远漏掉。现在载荷会在**宿主重连**、**本拍想要
  指示条却 0 命中**、以及**兜底轮询**（用户 15 s 内有键鼠输入则 5 s，空闲 30 s）时重新
  订阅并全量重放元素树，重放的首个 Add 清旧树并去重。
- **整片不着色，且只有重启资源管理器能恢复。**
  旧载荷退位时不退订，新载荷的 `AdviseVisualTreeChange` 可能返回 `E_UNEXPECTED` 后
  "放弃改色"；初始化重试 60 次后线程直接退出，DLL 却仍驻留 explorer，后续注入命中已加载
  模块、`DllMain` 不再执行——只能重启 explorer。现在**退位前先退订**，初始化失败改为
  **无限重试**（60 次后每 10 s 退避），任务栏重建或旧副本释放后能自愈。

## 变更

- **所有正常态指示条改为共用同一个画刷**：换色时只改这一个对象的 `Color`，全部短条
  同一刻变色，不再出现"改了几条、剩下几条还是系统色"。选中态仍走"元素 `Fill` + 画刷
  `Color`"双写（系统视觉状态会覆盖 `Fill`）；树重放与还原后重建画刷，避免句柄失效。

## 工程改进

- 注入失败不再静默：日志记 `inject failed: …`（同样的错只记一次），成功记 `inject ok: explorer pid=`。
- `payload/build.sh` 不再写死某台机器的 MSVC 路径，改为自动探测 VS / Windows SDK，
  可用 `MSVC_ROOT` / `SDK_ROOT` / `SDK_VER` 覆盖。
- 新增 `tools/check_payload_sync.py`：着色链路回归检查（C1 指示条有写入 / C2 订阅成功 /
  C3 未整片失效 / C4 重放后确实着色 / C5 正常态指示条共用同一画刷），只读日志、不改系统。
- 载荷新增诊断日志：`[Tree]`、`[Replay]`（含微秒级耗时）、`[IndFail]`、`[Shared]`。

## 下载与使用

- 附件：`随影ShadeBar_v1.3.1.exe`（单文件，免安装）。
- 双击运行，右键托盘图标可打开设置 / 暂停 / 开机自启 / 导出诊断包。
- 从 1.3.0 升级：直接替换 exe 即可，配置沿用 `%LOCALAPPDATA%\ShadeBar\config.json`。
- 若升级后第一次启动**仍不着色**，说明 explorer 里还残留旧版载荷：重启一次资源管理器即可，
  之后由新版载荷自己重放接管，不会再复发。

## 环境与限制

- Windows 11 26H2（Build 26300.9711）真机验证；更早版本未承诺。
- 需要注入 explorer（元素级着色的唯一可行路径）。写错会让任务栏重启，不会损坏系统。
- 新开窗口的指示条最多 5 秒跟上（15 s 内没动键鼠则 30 s），这是 CPU 与及时性的折中。
- 托盘字形图标可着色；微信、QQ 等程序自绘位图图标保持原样。
- 悬停高亮块尚未验证，未开放设置。
