**术语表**

| 术语 | 定义 |
|---|---|
| 采样区 | 任务栏右侧托盘区背后的一块屏幕矩形区域，用于计算背景亮度 |
| 判定色 | 自适应引擎输出的前景色，只有两种状态：亮端色（背景偏暗时用）或暗端色（背景偏亮时用） |
| 亮端色 / 暗端色 | 默认 `#FFFFFF` / `#000000`；开启自定义后可由用户指定 |
| 悬停块 | 鼠标悬停在任务栏图标上时出现的高亮背景矩形（Hover Highlight） |
| 指示条 | 运行中应用图标下方的横向短条（Running Indicator） |
| 注入 | 把着色模块加载进 `explorer.exe` 进程，篡改其内部 XAML 元素的 `Foreground` 属性 |
| 降级 | 注入不可用时，退化为不改变系统外观的低风险模式 |
| 感知亮度 Y | `Y = 0.299R + 0.587G + 0.114B`，输入为 0–255 的 sRGB 编码值，输出归一化到 0–1 |
| 鲁棒背景色（采样代表色） | 对采样区像素灰度做**截尾后取中位数**得到的背景代表色，**禁止使用算术平均**；用于抵抗任务栏自身文字/图标的高亮或低亮像素污染 |
| 自反馈震荡 | 改色后文字变白/变黑，自身成为采样区极值像素 → 下一帧判定翻转 → 颜色反复跳变的失效模式，必须由鲁棒统计量与遮罩双重抑制 |
| 完整性级别（IL） | Windows 强制完整性控制等级。`explorer.exe` 为 **Medium IL**，本产品同样以 Medium IL 运行，因此同级注入无需提权；若 explorer 被提升到 High IL（如以管理员运行）则注入会失败并触发降级 |
| 平滑 | 对连续采样结果做指数加权（EWMA），抑制抖动 |
| 语言资源 | 外置的文案键值对集合（`zh-CN` / `en` 两套），与 UI 逻辑代码分离，运行时可热切换 |

> **重要说明（写给工程师）**：Windows 没有修改任务栏时钟颜色的公开 API；Win11 22H2+ 任务栏已 XAML 化，时间与日期分别是 `DateTimeIconContent` 下的 `TimeInnerTextBlock` 与 `DateInnerTextBlock`。因此"真正改色"必然依赖注入 `explorer.exe`。本规格把交付拆成 L1（不注入、把采样与决策做对）到 L4（打磨），L1 是**必有**的地基，L2 起才有用户可见的改色效果。

## 1. 产品定位与一句话价值主张

**一句话价值主张**

> 随影 ShadeBar 让你的任务栏时间、日期和图标状态条，自动看齐身后壁纸的明暗 —— 你不用选颜色，也不会再看不见。

**定位**

- 它是 TranslucentTB 的**搭档**，不是替代品：TranslucentTB 负责"任务栏变透明"，随影负责"透明之后字还看得清"。
- 它是一个**极小的后台常驻工具**（便携单文件、托盘驻留、无主窗口打扰），不是主题美化套件。
- 它的核心机制是**闭环自适应**：局部实时采样 → 亮度判定 → 平滑防抖 → 注入生效 → 继续采样。用户唯一要做的事是"什么都不做"。

**与同类工具的差异（一句话，不做竞品分析）**

同类 CTM 类工具只提供"手工指定固定颜色"；随影提供"按背后真实背景实时自适应"，手工指定仅作为可选 fallback。

**三层价值**

1. **可读性**：任何壁纸下，任务栏文字与图标状态条都满足最低对比度。
2. **零维护**：不选色、不调参、不重启，换壁纸、动态壁纸、深浅主题自动跟上。
3. **低存在感**：≤ 4 MB、≤ 20 MB 内存、空闲 CPU < 0.1%，开了就忘。

## 2. 目标用户与使用场景

### 2.1 目标用户

| 画像 | 特征 | 关键诉求 |
|---|---|---|
| U1 美化型用户 | 已用 TranslucentTB / 第三方壁纸，喜欢纯净任务栏，常换壁纸 | 换壁纸后不用重新调颜色 |
| U2 动态壁纸用户 | 使用 Wallpaper Engine，壁纸颜色持续变化 | 静态设定无效，必须实时跟随 |
| U3 效率型用户 | 不希望后台软件吃资源、不希望有弹窗和更新提示 | 极轻、静默、开机即用 |
| U4 非中文用户 | 系统 UI 语言为英文（或其它语言）的美化用户 | 界面为英文，不需要靠猜菜单；语言可手动切换 |

> 界面语言策略（CR-01）：内置简体中文 + English 双语，首启跟随系统 UI 语言（2052 → 中文，其余 → English），设置页可改为固定语言，切换即时生效。

### 2.2 使用场景（均为可复现的具体场景）

| 编号 | 场景 | 当前痛点 | 随影的目标表现 |
|---|---|---|---|
| SC-01 | 用户把壁纸换成深色星空图，任务栏透明 | 时间与日期是黑色的，几乎完全看不见 | 采样到背景偏暗 → 时间/日期在 ≤1.5 s 内变白 |
| SC-02 | 用户把壁纸换成雪景/白墙 | 白色文字糊在亮色背景上 | 判定切到暗端色 → 文字变黑 |
| SC-03 | Wallpaper Engine 播放动态壁纸，画面从暗场过渡到亮场 | 手工固定颜色必然在某一半时间失效 | 采样跟随过渡，1 Hz 平滑切换，无闪烁 |
| SC-04 | 用户把鼠标移到任务栏图标上 | 悬停高亮块是浅灰半透明，叠在亮色壁纸上完全看不出选中态 | 悬停块按背景自适应深浅，选中态清晰可辨 |
| SC-05 | 用户开着微信/QQ，看运行中应用下方的指示条 | 指示条是白色 1–2 px，浅色壁纸下消失 | 指示条独立配色，始终可见 |
| SC-06 | 用户重启电脑 | 每次都要手动打开工具、再点一次"应用" | 计划任务自启，登录后静默驻留托盘，无 UAC 弹窗 |
| SC-07 | 用户在会议中把设置窗口关掉 | 窗口留在任务栏占位 | 关闭即最小化到托盘，托盘单击打开设置 |
| SC-08 | 用户暂时不想用，但也不想卸载 | 卸载重装成本高 | 托盘菜单"暂停自适应"，恢复系统原始外观，配置保留 |

| 安装包工具 | Inno Setup 6.7.3，`<user>\AppData\Local\Programs\Inno Setup 6\ISCC.exe` | 仅在明确要求时使用 |
| 代码签名 | 无证书，不做签名 | 首次运行会有 SmartScreen 提示，属预期行为 |

**权限前提**：本产品**不需要管理员权限**，以普通用户权限（medium 完整性级别）运行即可完成全部功能（含注入 `explorer.exe`）；**全生命周期 UAC 弹窗次数为 0**。
> 依据（SP-2 实测）：explorer.exe 以 medium IL 运行，同级进程对其执行 `OpenProcess` → `VirtualAllocEx` + `WriteProcessMemory` → `CreateRemoteThread(LoadLibraryW)` → 远程调用 → `FreeLibrary` 卸载全链路成功，explorer 未崩溃、pid 前后一致，Defender 实时保护开启下无拦截。此前"注入必须提权"的假设作废。

## 4. 范围界定

### 4.1 分层总览

| 层级 | 名称 | 交付物 | 用户可见效果 | 完成门槛 |
|---|---|---|---|---|
| **L1** | 无注入核心 | 采样引擎 + 判定引擎 + 设置界面 + 托盘 + 自启 + 便携打包 + 实时诊断面板 | 无改色效果（仅可选的主题联动兜底）；诊断面板能看到"实时判定色" | 判定结果与人工目测一致率 ≥ 95% |
| **L2** | 注入精确着色 | 注入器 + XAML 可视树遍历 + 时间/日期 Foreground 改写 + explorer 重启重挂 + 安全还原 | **时间、日期变色生效** | 时钟与日期在 10 类壁纸下均清晰可读 |
| **L3** | 高级着色 | 悬停高亮块 + 运行指示条着色，各自独立配色；自定义两端色；采样区微调 | 悬停块、指示条跟随自适应 | 悬停块与指示条分别通过对比度验收 |
| **L4** | 打磨 | 视觉对齐 Fluent、多显示器、DPI 变化、诊断导出增强、安装包（按需） | 体验完整 | 无 P1 以上缺陷遗留 |

> **交付节奏说明**：L1 是硬前置。L2/L3/L4 允许迭代发布，但每一层的验收基线（§9）必须各自全绿。**日常只出便携 exe，安装包仅在明确要求时额外出。**
> **v1.0.0 交付口径（已拍板，Q-02）**：v1.0.0 仅交付**单显示器 + 便携 exe**；多显示器支持（FR-41）与 Inno 安装包（FR-43）列为 **v1.1 候选**，不阻塞 v1.0.0 发布。
> **v1.5 范围裁决（A-29 真机证伪，优先于本表 L2/L3 行）**：用户执行 `tools/manual-sp2-verify.ps1`（报告 `sp2_manual_report.txt`），Phase A 叶函数近跳转探针 31 s 即 `EXPLORER_DIED`，Phase B `OnApplyTemplate` 模板内走查 `FAIL (maxRed=0)`（`HookFired ✅ / colorCount=1467 / walk hits=255`，t≈22.3 s explorer 死亡）——两条实现路线在**真实机器**上均证伪，近跳转 fail-fast 并非 AI 沙箱特异。基线红像素 28 → 复原后 28 无残留，explorer 与 TranslucentTB 均已恢复。**结论：v1.0.0 仅交付 L1；L2 / L3 着色能力移出 v1.0.0 且不再计划**。FR 条目保留不删除（需求溯源），逐条标注见 §4.6；§9 中相关验收项按「范围外」归类。

### 4.2 L1（MVP）明确包含

1. 单实例常驻进程，托盘驻留，无主窗口干扰。
2. 任务栏右侧采样区的**实时抓屏采样**（1 Hz），可在设置页"实时诊断面板"看到：采样区缩略图、鲁棒背景色（15% 截尾中位数）、判定色、感知亮度 Y、当前对比度。
3. 亮度判定与指数平滑防抖的**完整算法链**，参数全部可在设置页调整并立即生效。
4. 设置主页面（Fluent 风格、**中英双语**、可分组的可滚动表单）。
5. 托盘图标 + 托盘菜单（打开设置 / 暂停自适应 / 开机自启开关 / 退出）。
6. 开机自启动（Windows 计划任务方式）。
7. 配置持久化（JSON）与"恢复默认"。
8. 崩溃恢复：守护进程或自重启机制。
9. 日志文件与"导出一键诊断包"。
10. 便携单文件 exe 打包，文件名带版本号（`随影_ShadeBar_v1.0.0.exe`）。
11. 可选的主题联动兜底开关（默认关闭，见 §5 FR-04）。
12. MIT 许可证文件 + 仓库 README。
13. **中英双语界面**：两套文案资源外置、启动跟随系统 UI 语言、设置页可切换、切换即时生效（见 §5 FR-18 / FR-19）。

### 4.4 L2 / L3 / L4 范围

**L2 — 注入精确着色**

- 以**普通用户权限**（不请求提权）启动，定位 `explorer.exe`（取拥有任务栏窗口的进程，含 `Shell_TrayWnd`）。
- 通过 XAML 可视树定位 `DateTimeIconContent` → `TimeInnerTextBlock` / `DateInnerTextBlock`，改写 `Foreground`。
- 保存改写前的原值快照，退出或还原时写回。
- 监听 `explorer.exe` 重启，自动重挂（≤3 s）。
- 注入失败时按 §7 NFR-05 降级，且**不得**导致 explorer 崩溃（explorer 崩溃是本产品不可接受的严重缺陷）。

**L3 — 高级着色**

- 悬停高亮块（正常态 + 选中态）着色。
- 运行中应用下划线指示条着色。
- 悬停块与指示条**各自独立**的开关与颜色策略。
- 自定义亮端色 / 暗端色（替代纯黑纯白）。
- 采样区域微调（水平起点、宽度、垂直内缩）。

**L4 — 打磨**

- Fluent / Mica / 圆角 / Segoe UI Variable 全量视觉对齐。
- 多显示器（每屏独立采样与判定）。
- DPI 与分辨率变化自适应。
- 诊断包增强（含 hook 成功/失败明细、对比度曲线）。
- Inno Setup 安装包（按需）。
- 日志轮转。

### 4.5 永久不在范围（Out of Scope，任何层级都不做）

- 修改系统注册表以实现"系统级"文字颜色（会污染其它应用）。
- 以驱动方式 hook（风险过高）。
- 修改其它进程的窗口。
- 收集任何用户数据、任何联网行为。

### 4.6 v1.5 范围裁决：L2 / L3 着色能力永久移出

**真机证据**（用户执行 `tools/manual-sp2-verify.ps1`，报告 `sp2_manual_report.txt`）：

| 阶段 | 结果 | 判读 |
|---|---|---|
| Phase A 叶函数近跳转探针（只计数） | `EXPLORER_DIED`，31 s 即死 | 近跳转 fail-fast **不是 AI 沙箱特异**，是真实机器缺陷 |
| Phase B `OnApplyTemplate` 模板内走查改色 + 像素轮询 | `FAIL (maxRed=0)`；`HookFired ✅ / colorCount=1467 / walk hits=255`；t≈22.3 s explorer 死亡 | 模板内走查在真机同样不安全，且未产生任何改色像素 |

> ① **记法**：按 WinUI / XAML `#AARRGGBB`，`alpha = 0x38`（约 **22%**），即**半透明白**；架构写带 alpha、需求基线写不透明纯白，属**两份文档既有冲突，不是实现偏差**，工程师采用架构值属正确理解。
> ② **用途与观感**：S-35（运行中指示条固定色）、S-37（悬停高亮块固定色）都是**叠在任务栏 / 壁纸之上的装饰性覆盖层，不是文字**。不透明 `#FFFFFF` 会形成生硬白块、遮挡壁纸，与原始需求 10「所有外观使用或接近 Windows 11 原生风格（Fluent / Mica / 圆角）」冲突，**在深色任务栏上尤其刺眼**；22% 白色既能显出选中态，又保留底层质感与半透明层次。
> ③ **结论**：需求基线表格统一为 `#38FFFFFF`，取值范围明确为含 alpha 的 `#AARRGGBB`（禁用 `00` 全透明），颜色选择器须允许调 alpha；**工程师现有实现无需改代码**。A-12「恢复默认」按新默认值校验。
> ④ **保留意见（不改默认值）**：S-35 是 1–2 px 细线，22% alpha 在深色任务栏上可能偏淡；若后续实测不可辨，由主理人另发变更，**v1.5 不擅自为 S-35 设不同默认值**，避免两份文档再次分歧。

> ⑥ **冲突状态（v1.6 确认）**：**S-35 / S-37 默认值冲突已于 v1.5 本注关闭**（采用 `#38FFFFFF`，需求表格与工程师实现一致）。**QA 按正常核对项处理，不再作为观察项或待裁定项**；QA 报告中「待 PM 裁定、保持观察项」为消息交叉造成的过期状态，由 QA 自行更正。

## 7. 非功能需求

| 编号 | 类别 | 需求 | 验收标准（可客观测量） |
|---|---|---|---|
| NFR-01 | 体积 | 便携 exe ≤ **4 MB**（不含 pdb） | `dir` 查看单文件大小 ≤ 4096 KB；**以关闭 `cfg(feature="verify")` 的发布版为准**（取证编排版体积不作验收依据，见 §7.1 K-07） |
| NFR-02 | 内存 | 常驻工作集 ≤ **20 MB**（含 L2 注入场景下的主进程；不含被注入的 explorer 增量） | 运行 30 分钟后任务管理器工作集 ≤ 20 MB |
| NFR-03 | CPU 占用与采样耗时（双口径） | **主判据（硬性、门禁）**：10 分钟平均**单核 CPU 占用 < 0.1%**。本需求的意图是"不把用户电脑拖慢"，用进程实际消耗的 CPU 时间度量，**不用墙钟耗时替代**。<br>**辅助判据（墙钟口径，保留 max 上限）**：单次采样墙钟 `cost_us` 的 **p95 ≤ 10 ms、max ≤ 15 ms**。测量范围为 `sampler.rs:835` 的 `Instant::elapsed()` 所包裹的一段：包含真实 BitBlt 抓屏 + 直方图 + 判定，**不包含** UIA 与几何计算。<br>**口径说明（关键）**：`cost_us` 包含 DWM 合成 / 抓屏的**阻塞等待**，因此**不作为 CPU 性能指标**。T04 真机交叉核算：10 分钟 `cost_us` 累计 2.6912 s，而 `GetProcessTimes` 报进程 CPU 仅 0.1875 s，差 2.5037 s 属阻塞等待而非 CPU 消耗；因此原「单次 ≤ 5 ms」墙钟判据（241/592 超线）被判定为**口径错误**，予以废止，但不删除墙钟要求、也不放宽为 20 ms 了事。<br>**双口径不得互相替代**：CPU 达标不得豁免墙钟超线；墙钟超线也不得反推 CPU 不达标 | **测量方法（QA 必须照此取证）**：①`GetProcessTimes` 取 10 分钟窗口内 `KernelTime + UserTime` 的增量，单核 CPU% = CPU 时间增量 ÷ 墙钟时长 × 100；全机 CPU% = 单核 CPU% ÷ 逻辑核心数；②`cost_us` 由代码内 `Instant::elapsed()` 输出，样本数 **≥ 500**（T04 full 档：600184 ms / 592 samples / 0 bad / 0 flips）；③两项分别计算、分别记录，**三项判据须同时满足**：单核 CPU < 0.1%（T04 实测 0.0312%，全机 0.0026%）、`cost_us` p95 ≤ 10 ms（实测 6.725 ms）、`cost_us` max ≤ 15 ms（实测 11.721 ms）；④若墙钟超线，登记为性能缺陷观察项并复测，但不得据此把 CPU 判据改回墙钟口径 |
| NFR-04 | 启动耗时 | 双击到托盘图标可交互 ≤ **1.5 s**（冷启动，SSD） | 连续 5 次冷启动取中位数 ≤ 1.5 s |
| NFR-05 | 降级行为 | 降级触发条件为三类：**①注入失败**（`OpenProcess` / `VirtualAllocEx` / `CreateRemoteThread` 任一失败）、**②Windows 版本不匹配**（XAML 结构变化）、**③用户主动设为仅 L1**。降级后自动切为 L1 模式：不改变系统外观、核心采样与设置可用、托盘图标显示"受限"角标（**仅在降级时出现，普通权限下属正常状态不带角标**）、设置页顶部横幅说明原因与自助排查建议（不提供提权按钮） | 三类降级场景下均可正常打开设置、正常采样、不崩溃、不弹模态阻断框；无管理员权限**不构成**降级理由 |
| NFR-06 | 崩溃恢复 | 主进程异常退出后 ≤ 3 s 自动重启；连续 5 次失败后停止并提示。注入模块在宿主断开后 ≤ 10 s 自行还原并卸载 | 强杀进程 3 s 内复活；强杀 5 次后停止；强杀后系统外观自动恢复 |
| NFR-07 | 多显示器 | 1.x 以主显示器为验收基准；多显示器下不得出现采样错位导致颜色乱跳（允许仅对主屏生效），L4 支持每屏独立 | 双屏同壁纸与双屏异壁纸两种布局下，主屏表现正确且无闪烁；程序不报错 |
